Pre question 1: Far fewer test cases, because the grammar shrinks the search space from about 254^3 = 16.4 million inputs to 62^3 = 238,328, roughly 69 times smaller.
Pre question 2: Wall clock time should drop by about the same factor, since each test case still costs about the same to execute.
Post question 1: The average of 246,934 test cases is close to 238,328, the size of the grammar's search space, which is what random guessing predicts. The ratio to Objective 2 is not exactly 1/69 because a few trials of a random process are noisy.
Post question 2: Grammar-based fuzzing is much faster at reaching well-formed inputs, but it never tests malformed inputs, so bugs in input validation or parsing of unexpected formats are missed. It also requires someone to know or write the grammar.
Post question 3: Use feedback about which code each input executed, mutate inputs that made progress instead of generating from scratch, and execute test cases faster than system().
